\begin{abstract}
EV charging usability depends on factors like connector compatibility, operating hours, access conditions, and network memberships. Comparing existing infrastructure data and semantic models reveals critical representation gaps. To address these, we present PluggedIn, a relational data model centered on vehicle-specific practical usability that integrates direct connector compatibility, driver network memberships, and structured operating periods, laying the groundwork for future knowledge graphs. The project repository and data models are available at \url{https://github.com/chohoon901/PluggedIn}.
\end{abstract}

\keywords{EV charging, relational data modeling, SQLite, connector compatibility, data accessibility}

\section{Problem Definition}
Our goal is to enable drivers and fleet managers to retrieve station availability, connector compatibility, operating hours, and payment conditions. Flat infrastructure lists fail to capture vehicle-to-port suitability, access restrictions, and membership constraints. 

We link charging stations to structured operating periods, ports, standardized connector types, and organizational roles, while explicitly associating drivers with network memberships. Our database answers a core operational question: \textit{``Can a specific vehicle charge at this station through a direct connection, and is it open and accessible under the driver's network membership?''}

\section{Proposed Relational Model}
\subsection{Station, Organization, and Core Entity Relations}
\textbf{Station} records coordinates, address, parking, access and vehicle-class restrictions, guest payment, and status. \textbf{Organization} distinguishes owner, operator, and network roles through an ISA mapping. Relations use integer surrogate primary keys; organization subtypes share the parent key. Business identifiers are candidate keys where applicable.

\subsection{Ports, Operating Periods, and Adapter Relations}
\textbf{OperatingPeriod} replaces unstructured free-text hours with structured daily opening and closing times. \textbf{Port} tracks specific station outlets, current types, and power capacities, standardized via \textbf{ConnectorType}. \textbf{Adapter} handles real-world connector mismatches between plug and socket types by linking separate connector specifications.

\subsection{Vehicles, Drivers, and Membership Relations}
\textbf{Vehicle} stores VIN, plate, make, model, class, range, and maximum charging power; \textbf{Driver} stores personal and carrier details. \textbf{vehicle\_accepts} links vehicles to connector types, and \textbf{membership} links drivers to networks with validity dates. Payment-method information belongs to \textbf{network}.

\subsection{Relationship Mapping and Integrity Constraints}
Foreign keys represent many-to-one links. Candidate keys enforce \texttt{UNIQUE} and \texttt{NOT NULL}; \texttt{CHECK} constraints limit current types, coordinates, positive values, and opening periods. SQLite enables foreign keys on every connection, with schema-defined cascade and restriction rules. Application validation handles input formats and aggregate participation, retaining explicitly incomplete source evidence.

\section{Relational Operations}
\subsection{Creating and Populating Relations}
PluggedIn implements 13 SQLite tables with primary, foreign, candidate-key, and domain constraints. The following SQL defines \textbf{Port}:

{\footnotesize
\begin{verbatim}
CREATE TABLE port (
    port_id INTEGER PRIMARY KEY,
    station_id INTEGER NOT NULL
        REFERENCES station (station_id) ON DELETE CASCADE,
    number SMALLINT NOT NULL CHECK (number > 0),
    connector_type_id INTEGER NOT NULL
        REFERENCES connector_type (connector_type_id),
    power_kw NUMERIC(6,1) CHECK (power_kw > 0),
    current_type VARCHAR(5)
        CHECK (current_type IN ('AC', 'DC')),
    quantity SMALLINT NOT NULL DEFAULT 1
        CHECK (quantity > 0),
    CONSTRAINT ak_port UNIQUE (station_id, number));
\end{verbatim}
}

Foreign keys link ports to stations and connector types. \texttt{UNIQUE (station\_id, number)} prevents repeated numbers within a station; station deletion cascades to ports.

Sample data is populated using SQLAlchemy ORM, with duplicate checks to maintain data integrity.

\subsection{SELECT Queries}
The following query finds stations sharing a stored connector ID with Vehicle 2 by joining \textbf{Port} and \textbf{VehicleAccepts}.

{\footnotesize
\begin{verbatim}
SELECT DISTINCT p.station_id
FROM port AS p JOIN vehicle_accepts AS va
    ON p.connector_type_id = va.connector_type_id
WHERE va.vehicle_id = 2;
\end{verbatim}
}

The next query counts compatible port records per station using \texttt{COUNT(*)} and \texttt{GROUP BY}.

{\footnotesize
\begin{verbatim}
SELECT p.station_id, COUNT(*) AS compatible_port_count
FROM port AS p JOIN vehicle_accepts AS va
    ON p.connector_type_id = va.connector_type_id
WHERE va.vehicle_id = 2 GROUP BY p.station_id;
\end{verbatim}
}

On the unchanged sample, both queries return station 1, with one matching port record. Full evaluation additionally interprets connector aliases and checks hours, access, and payment.

\subsection{INSERT, UPDATE, and DELETE Operations}
The following transaction demonstrates relationship and attribute updates without retaining changes.

{\footnotesize
\begin{verbatim}
BEGIN;
INSERT INTO vehicle_accepts (vehicle_id, connector_type_id)
VALUES (1, 1);
UPDATE port SET power_kw = 120.0 WHERE port_id = 1;
DELETE FROM vehicle_accepts
WHERE vehicle_id = 1 AND connector_type_id = 1;
ROLLBACK;
\end{verbatim}
}

These statements temporarily add J1772 support to Vehicle 1, update Port 1, and remove that association. \texttt{ROLLBACK} leaves the sample unchanged.

\section{Architecture and User Interface}

PluggedIn is a server-rendered FastAPI application using local SQLite. The presentation (\texttt{pl}), domain (\texttt{cmn}), and data access (\texttt{dal}) layers are connected in \texttt{main.py}. CRUD operations for drivers, vehicles, and memberships, station searches, and detail pages work without JavaScript. Leaflet displays OpenStreetMap tiles as an optional map.

\texttt{cmn} validates input and evaluates hours, access, connectors, and payment as \textbf{Pass/Fail/Unknown}, yielding \textbf{Available/Unavailable/Needs Review}. \texttt{dal} uses SQLAlchemy ORM and bound parameters; a unit of work commits or rolls back related changes per use case. Forms redirect with HTTP 303 on success or return HTTP 400 HTML preserving input; API duplicate keys return HTTP 409.

\section{Reproducibility and Evaluation}

The application uses Python 3.12 or later, FastAPI 0.162.0, and SQLAlchemy 2.0.55. \path{dal/scripts/schema.sql} defines 13 tables and 65 columns. Section 3 describes the main queries; \path{dal/repositories/} contains ORM implementations, and \path{README.md} provides setup instructions.

Install \path{requirements.txt} and the project in a virtual environment, validate the bundled sample with \texttt{validate\_db}, then start uvicorn. \texttt{import\_sample} rebuilds data into a fresh directory. UNIQUE and FK constraints enforce integrity. Station owner/operator/network references allow NULL. Network deletion cascades to memberships but may be blocked by referencing stations.

The repository records 170 passing tests, including browser tests, and 91 subtests on 27 October 2026. Team-authored code uses the MIT License; bundled Leaflet 1.9.4 uses BSD 2-Clause, with its full license text included in the repository.

\section*{Relations and Constraints}
\label{sec:relations-constraints}
Underlining denotes a primary key (PK). CK denotes an additional candidate key enforced by \texttt{UNIQUE} and \texttt{NOT NULL}. PKs are generated integers, except for organization subtypes, which share the superclass key. All PK/CK attributes are mandatory. Other attributes are nullable unless marked mandatory below.

\begin{enumerate}
\renewcommand{\labelenumi}{(\arabic{enumi})}
\setlength{\itemsep}{2pt}
\setlength{\parsep}{0pt}
\setlength{\parskip}{0pt}

\item \textbf{organization} (\underline{organization\_id}, name, website).\\
CK: \{name\}. Specialization is overlapping and total: each organization has at least one role.

\item \textbf{site\_owner} (\underline{organization\_id}, business\_type).\\
PK/FK: organization\_id references organization.organization\_id, mandatory. No additional CK.

\item \textbf{operator} (\underline{organization\_id}, support\_phone).\\
PK/FK: organization\_id references organization.organization\_id, mandatory. No additional CK.

\item \textbf{network} (\underline{organization\_id}, payment\_method).\\
PK/FK: organization\_id references organization.organization\_id, mandatory. No additional CK.

\item \textbf{station} (\underline{station\_id}, latitude, longitude, name, street, city, province, status, access\_restriction, accepts\_guest\_payment, max\_vehicle\_class, has\_truck\_parking, owner\_id, operator\_id, network\_id).\\
CK: \{latitude, longitude\}. Latitude is between -90 and 90, and longitude between -180 and 180. FK: owner\_id references site\_owner.organization\_id and operator\_id references operator.organization\_id, network\_id references network.organization\_id, all optional. Accepts\_guest\_payment and has\_truck\_parking are mandatory Booleans, both defaulting to \texttt{FALSE}.

\item \textbf{connector\_type} (\underline{connector\_type\_id}, name, max\_power\_kw).\\
CK: \{name\}. Max\_power\_kw must be positive when supplied.

\item \textbf{port} 
(\underline{port\_id}, station\_id, number, connector\_type\_id, power\_kw, current\_type, quantity).\\
CK: \{station\_id, number\}. FK: station\_id references station.station\_id and connector\_type\_id references connector\_type.connector\_type\_id, both mandatory. Number must be positive. Quantity is mandatory, positive, and defaults to 1. When supplied, power\_kw must be positive and current\_type must be \texttt{AC} or \texttt{DC}.

\item \textbf{operating\_period} (\underline{operating\_period\_id}, station\_id, day, open\_time, close\_time).\\
CK: \{station\_id, day, open\_time\}. FK: station\_id references station.station\_id, mandatory. All attributes are mandatory. Day is one of \texttt{Mon}, \texttt{Tue}, \texttt{Wed}, \texttt{Thu}, \texttt{Fri}, \texttt{Sat}, or \texttt{Sun}. Close\_time must be later than open\_time.

\item \textbf{adapter} (\underline{adapter\_id}, model, manufacturer, max\_power\_kw, from\_connector\_type\_id, to\_connector\_type\_id).\\
CK: \{model\}. Both connector attributes are mandatory FKs to connector\_type.connector\_type\_id. The two connector IDs must differ. Max\_power\_kw must be positive when supplied.

\item \textbf{vehicle} (\underline{vehicle\_id}, vin, licence\_plate, make, model, class, range\_km, max\_charge\_kw).\\
CK: \{vin\}. Range\_km and max\_charge\_kw must be positive when supplied.

\item \textbf{vehicle\_accepts} (\underline{vehicle\_accepts\_id}, vehicle\_id, connector\_type\_id).\\
CK: \{vehicle\_id, connector\_type\_id\}. FK: vehicle\_id references vehicle.vehicle\_id and connector\_type\_id references connector\_type.connector\_type\_id, both mandatory.

\item \textbf{driver} (\underline{driver\_id}, licence\_number, name, carrier\_name).\\
CK: \{licence\_number\}.

\item \textbf{membership} (\underline{membership\_id}, driver\_id, network\_id, start\_date, end\_date).\\
CK: \{driver\_id, network\_id, start\_date\}. FK: driver\_id references driver.driver\_id and network\_id references network.organization\_id, both mandatory. End\_date is NULL or on or after start\_date.
\end{enumerate}

\noindent\textit{Participation and additional rules.}
Application checks enforce organization roles and aggregate minimum counts: ports/hours per station, stations per owner/operator, and connectors per vehicle. Explicit \texttt{INCOMPLETE} station metadata permits missing port/hour evidence. Overlapping operating periods and memberships remain allowed.

\medskip
\noindent\textit{Referential actions.}
Cascade deletion applies from organizations to subtypes, stations to ports and operating periods, vehicles to vehicle\_accepts, and drivers or networks to memberships. Other FKs block deletion while dependent rows remain; these restrictions can also block a cascade.

\medskip
\noindent\textit{Implementation boundary.}
SQLite foreign-key enforcement must be enabled on every connection. Optional numeric attributes allow NULL despite positivity checks. Rejecting empty mandatory text values requires additional validation.
